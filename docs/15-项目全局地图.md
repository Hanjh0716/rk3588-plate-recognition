## 一、一句话看清整个项目

```
摄像头看到一辆车
      ↓
①【找到车牌在哪】  ← 检测（YOLO）
      ↓
②【读出车牌上的字】← 识别（LPRNet）
      ↓
③【输出车牌号】   "京A·12345"
      ↓
④【做点什么】     记录 / 报警 / 开闸 / 云台对准
```

**你的项目 = 把这条链做出来，并且让它跑在 RK3588 的 NPU 上。**

中间所有的技术，都是为这条链服务的。

## 二、⭐ 五层结构（核心框架）

整个技术栈分成 5 层。**每一层回答一个问题**：

```
┌──────────────────────────────────────────────────────────────┐
│ 第 5 层  应用层     "我要做一个什么系统？"                      │
│          车牌识别 + 云台伺服 + 上位机（毕设）                    │
├──────────────────────────────────────────────────────────────┤
│ 第 4 层  算法层     "怎么从一张图里找出车牌、读出字？"           │
│          YOLO 检测  +  LPRNet 识别     ← ★ 你现在在这一层      │
├──────────────────────────────────────────────────────────────┤
│ 第 3 层  运行层     "模型在哪跑、怎么喂数据、怎么拿结果？"       │
│          onnxruntime / NPU / librknnrt / 推理 / 张量           │
├──────────────────────────────────────────────────────────────┤
│ 第 2 层  格式层     "模型怎么变成硬件能执行的东西？"             │
│          PyTorch → ONNX → RKNN，Toolkit2 编译器，量化          │
├──────────────────────────────────────────────────────────────┤
│ 第 1 层  环境层     "这些东西装在哪、怎么不互相打架？"           │
│          Windows / WSL2 / Linux / 三个 Python 环境 / 依赖       │
└──────────────────────────────────────────────────────────────┘
```

**关键认知：这五层是"从下往上依赖"的。**

```
第4层（算法）  需要  第3层（运行）跑得起来
第3层（运行）  需要  第2层（格式）有模型
第2层（格式）  需要  第1层（环境）装好工具
```

**所以低层的问题会伪装成高层的 bug。**
比如："模型算出来的框是错的" → 可能是第 1 层的环境装错了版本。
**这就是为什么排查问题要"从下往上查"。**

## 三、每一层：你学了什么

### 🔵 第 1 层：环境层 ✅ 已完成

| 知识点 | 一句话本质 |
|---|---|
| **WSL2** | 在 Windows 里跑的一个真 Linux，共用硬盘但文件系统是隔离的 |
| **虚拟环境**（venv / conda） | 给每个项目一套**独立的 Python 和包**，互不污染 |
| **`which python3`** | 确认"我现在用的到底是哪个 Python"——**环境问题的第一诊断命令** |
| **`/mnt/d/`** | WSL 里访问 Windows D 盘的路径（`D:\` → `/mnt/d/`） |
| **PATH** | 系统找命令的**顺序表**；"激活环境"本质上就是改这张表 |
| **`pip` / `conda`** | 装包工具；装错环境 = `ModuleNotFoundError` |
| **动态库（.so）** | 程序运行时依赖的共享库；版本不对就 `undefined symbol` |

**你在这层的实战**：踩了 ~10 个坑（conda ToS、torch 的 `iJIT_NotifyEvent`、`onnx.mapping`、protobuf 冲突、execstack…），**并且总结出了 `docs/10-环境排查方法论.md`**。

---

### 🔵 第 2 层：格式与工具链层 ✅ 已完成

**核心链条（背下来）**：

```
PyTorch 训练 → .pt/.pth
      ↓ 导出
   ONNX (.onnx)        ← 通用交换格式
      ↓ RKNN-Toolkit2（在 PC 上转换）
   RKNN (.rknn)        ← 瑞芯微私有格式，绑定芯片
      ↓ 拷到板子
librknnrt / lite2      ← 板端运行时，指挥 NPU
```

| 知识点 | 一句话本质 |
|---|---|
| **ONNX** | 通用模型交换格式。**AI 界的 Gerber**——谁都能读，但谁都不能直接跑 |
| **RKNN** | 瑞芯微私有格式。**已经为这颗 NPU 编译好的产物**，绑定芯片型号 |
| **RKNN-Toolkit2** | PC 上的**编译器 + 模拟器**（像 gcc）。**板子上没有它** |
| **librknnrt** | 板端**运行时**（像 libc），真正指挥 NPU 干活 |
| **算子（operator）** | 模型的基本运算单元（卷积、加法、激活…）。**NPU 只认它硬件里固化的那些** |
| **量化** | FP32 → INT8。体积约 1/4，速度翻倍，精度通常掉 <1% |
| **版本对齐** | Toolkit2（PC）= librknnrt（板）= lite2（板），三者必须一致 |

**你在这层的实战**：装好 Toolkit2、把 `onnx2rknn.py` 跑通、把板上 `librknnrt` 从 1.4.0 升到 2.3.0。

---

### 🔵 第 3 层：运行与推理层 ✅ 基本完成

| 知识点 | 一句话本质 |
|---|---|
| **推理（inference）** | **把数据喂进模型，拿到一堆数字出来**。就这么简单 |
| **张量 / ndarray** | 多维数组。模型吃进去、吐出来的都是它 |
| **shape** | 数组的形状。图像是 `(高, 宽, 通道)`，模型输入是 `(1, 3, 高, 宽)` |
| **NCHW / NHWC** | 两种维度顺序约定。**接错了必出错**，而且报错很难懂 |
| **归一化** | 把像素 0~255 除以 255 变成 0~1（模型训练时就这么喂的） |
| **sigmoid** | 把任意实数压到 **0~1**，用来表示"概率/比例" |
| **softmax** | 让一组数**加起来等于 1**（互斥分类）。判断方法：`sum()` 是不是 1 |
| **仿真 vs 真机** | PC 上假装有 NPU（慢，但能验证流程）；真机才用得上 NPU |

**你在这层的实战**：搞清了 `load_onnx → build → init_runtime → inference` 这条链，以及"`.rknn` 不能在 PC 仿真"这个坑。

### 🔴 第 4 层：算法层 👈 **你现在在这一层**

**这一层回答：模型吐出来的那些数字，怎么变成图上的框？**

| 知识点 | 一句话本质 | 你的状态 |
|---|---|---|
| **letterbox** | 保比例缩放 + 灰边填充，**避免图片被拉变形** | 🟡 用过，还没自己写 |
| **网格 grid** | 把图切成 80×80 个格子，**每格独立预测** | 🟡 |
| **锚框 anchor** | **预设的框形状**（3 种宽高比）。模型只学"微调多少"，不学"框多大" | 🟡 |
| **步长 stride** | 一个格子对应原图多少像素（8 / 16 / 32） | 🟡 |
| **通道拆解** | `255 = 3 anchor × 85`；`85 = 5 + 80` | 🟢 刚搞懂 |
| **解码 decode** | 把"相对格子的偏移"算成**绝对坐标** | 🔴 **正在攻** |
| **objectness (obj)** | "**这格有没有东西**"的分数。用来干掉背景垃圾 | 🟢 刚搞懂 |
| **置信度** | `obj × 类别分数`，两个都要高才算数 | 🟢 |
| **IoU** | 两个框的**重叠程度** = 交集 ÷ 并集 | 🔴 |
| **NMS** | 一个目标只留**最自信的那个框**，其余按 IoU 淘汰 | 🔴 |
| **反向映射** | 把 letterbox 坐标换算回**原图坐标**（减 pad、除以 r） | 🟡 |

**图例**：🟢 懂了 ｜ 🟡 一半 ｜ 🔴 还没真正到手

**你在这层的实战**：写了 `yolo_inspect.py`（看输出）、`yolo_probe.py`（看排布）、`yolo_infer.py`（完整后处理），**流水线已验证跑通**——但大部分代码是我写的，**这正是你现在要补的**。

## 七、为什么你会觉得"一头雾水"——三个原因

### ① 没有地图（本文档解决）

知识是**按"用到才讲"**给的，好处是快，坏处是**不成体系**。
你学了 WSL、ONNX、anchor、NMS、softmax……但**不知道它们各自站在哪一层**。

**现在有了**：遇到任何一个概念，先问"它属于第几层"。

### ② 我最近给代码给多了

从 `yolo_inspect.py` 开始，4 个脚本都是我写的，你负责粘贴运行。
**看别人写的代码，大脑只做一件事："哦，好像有道理"**——这是最浅的一层。
**只有自己写、卡住、报错、改对，它才变成"我的"。**

（这是我的方法错误，不是你的问题。而且第 4 层恰好是整个项目**技术含量最高**的地方，最不该被跳过。）

### ③ 第 4 层本身就是最抽象的一层

前面三层都是"装东西、配东西"，**看得见摸得着**。
第 4 层是"**把 4 维数组里的数字翻译成图上的框**"——**没有直觉可依赖，只能硬啃。**

**好消息**：它是**唯一的**一座高山。翻过去，第 5 层全是"用现成的东西"。

## 八、一张速查：遇到问题时该查哪一层

| 现象 | 大概率是哪一层的问题 | 先做什么 |
|---|---|---|
| `ModuleNotFoundError` | 第 1 层 环境 | `which python3` |
| `undefined symbol` / 库冲突 | 第 1 层 环境 | 看 `.so` 版本 |
| `.rknn` 加载失败 / 版本不匹配 | 第 2 层 格式 | 查三处版本号 |
| 转换时报"算子不支持" | 第 2 层 格式 | 换算子 / 回退 CPU |
| 输出 shape 不对 | 第 3 层 运行 | 打印 shape |
| **框位置偏、大小不对** | **第 4 层 算法** | **查 letterbox 的 r 和 pad** |
| **满屏框** | **第 4 层 算法** | **查 obj、查 NMS** |
| 一个框都没有 | 第 4 层 或 模型本身 | 降阈值 → 换图 → 查 obj |
| 程序慢 | 第 3/5 层 | `which` 是不是走了 CPU |
