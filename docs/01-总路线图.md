# 总路线图与硬件采购策略

> 这份文件回答两个问题：**8 周怎么走**、**什么时候买什么硬件**。

---

## 核心原则

> **先零成本学到有把握，再花钱买硬件。**

你的项目里最难的部分——模型转换、算子兼容、INT8 量化掉点——**全部可以在你现在的电脑上完成**，不需要任何板子。

RKNN-Toolkit2 提供**仿真推理模式**，能在 x86 电脑上直接跑。这意味着：

- 你现在就能把"ONNX → RKNN 转换"这段最难的流程摸透
- 板子到货那天，你已经有把握了，不是从头开始
- 如果先买板子再卡在模型转换上，你分不清是板子问题还是技术问题

### 第 2–3 周 — Python 基础

| 任务 | 产出 |
|---|---|
| 语法：变量/循环/函数/字典/文件 | 能写小工具脚本 |

👉 看 `03-Python练习计划.md`（14 天，每天 1.5–2 小时）

**毕业标准**：能独立写出"批量处理目录下所有图片、画框、保存、写报告"的脚本。

> 你有 FreeRTOS/C 基础，Python 语法对你是**降级不是升级**。真正的新东西是 NumPy 的向量化思维——**别写逐元素的 for 循环**，这是新手最大的坎。

---

### 第 4 周 — 深度学习最小必要集

| 任务 | 产出 |
|---|---|
| 理解张量、模型推理是什么 | 知道模型输入输出的形状 |
| 装 PyTorch (CPU 版) | `import torch` 能跑 |
| 理解"预训练模型"和"推理" | 能加载一个现成模型跑一次 |

**不需要学**：反向传播数学、自己写网络、训练大模型。**你要做的是用现成模型，不是造模型。**

> ⚠️ **第 4 周开工第一件事是解决 Python 版本**：PyTorch 目前没有 Python 3.14 的官方包（[pytorch#156856](https://github.com/pytorch/pytorch/issues/156856) 还开着），而你现在的 `py-basics/.venv` 就是 3.14。**单独建一个 3.10 的环境**（别动 `py-basics`），见下面「环境分层」。

---

### 第 5 周 — 车牌检测（电脑上，零成本）

| 任务 | 产出 |
|---|---|
| 用 YOLO 跑通车牌检测 | 一张图 → 画出车牌框 |
| 手机拍车牌视频当输入 | 视频流检测 |
| 收集/整理车牌数据集 | `~/datasets/` 下有数据 |

**这一步全程零成本**，用你电脑的 CPU 就能跑（慢一点没关系）。

---

### 第 6 周 — 模型转换 ⭐ 最关键的一周

| 任务 | 产出 |
|---|---|
| 装 RKNN-Toolkit2 (x86) | 工具链可用 |
| PyTorch → ONNX → RKNN | 拿到 `.rknn` 文件 |
| INT8 量化 + 精度对比 | 知道量化掉了多少点 |
| 仿真推理验证 | 在电脑上验证转换后的模型 |

**这一周决定项目成败。** 常见问题：
- **算子不支持** → 需要改网络结构
- **精度掉太多** → 需要调整量化校准数据集
- **输入输出形状不匹配** → 需要对齐前后处理

在电脑上把这些问题解决掉，**再买板子**。

---

### 第 7 周 — 采购 + 上板

**这时候你已经知道该买什么了。**

采购清单见文末。

| 任务 | 产出 |
|---|---|
| 板子开机 | 串口看到内核日志 |
| 验证 NPU | `cat /sys/kernel/debug/rknpu/version` 有输出 |
| 跑通官方例程 | `rknn_model_zoo` 的 YOLOv8 demo |
| 部署自己的模型 | `.rknn` 在板子上跑起来 |

## 时间表（2026-09-22 起点）

> **你的实际速度**：14 天的 Python 计划 3 天干完（9/19 → 9/22）。下面按"保持每天 2–3 小时、第 6 周会卡一下"估算。

| 里程碑 | 预计 | 内容 | 卡点风险 |
|---|---|---|---|
| **M1 阶段⓪毕业** | 9/23–9/24 | Day 13 + Day 14（批处理 + 错误处理 + 报告脚本） | 低 |
| **M2 环境就位** | 9/23–9/27 | 建 Python 3.10 环境、装 PyTorch(CPU)、跑通一个预训练模型 | conda/PyTorch 下载慢 |
| **M3 板子过关** ⭐ | 9/24–9/28 | 验机 + `rknn_model_zoo` 官方 YOLOv8 demo 在板子上跑通（实测 NPU FPS） | 中（镜像/WiFi 模块） |
| **M4 电脑上检出车牌** | 9/28–10/5 | YOLO 跑通"图 → 车牌框"；拍 100–200 张、标注 ~100 张、微调 yolov8n | **数据标注耗时** |
| **M5 转成 .rknn** ⭐⭐ | 10/5–10/14 | RKNN-Toolkit2 → ONNX → RKNN、INT8 量化 + 精度对比、仿真推理 | **最高**（算子/量化/前后处理） |
| **M6 上板跑自己的模型** | 10/14–10/20 | 自己的 `.rknn` 在板子上出车牌框 | 中 |
| **M7 端到端出车牌号** | 10/20–10/27 | 检测 + LPRNet/PPOCR 字符识别 = 完整车牌号（电脑 + 板子各跑一次） | 低（官方有例程） |
| **M8 实时视频流** | 10/27–11/3 | USB 摄像头 → 检测 → 识别 → 显示，测帧率 | 中 |
| **M9 稳定+调优** | 11/3–11/15 | 连续跑几小时不崩、多线程/零拷贝、结果存储 | 低 |

**结论（三种情况）**：

| 情况 | "板子上跑通完整车牌识别" | 条件 |
|---|---|---|
| 乐观 | **10 月中（10/15 前后）** | 每天 3–4 小时，第 6 周转换一次过 |
| 现实 | **10 月底（10/25 前后）** | 每天 2 小时，转换卡 3–5 天 |
| 保守 | **11 月中** | 每天 1 小时，或转换卡到换方案 |

**三个最大变量**（按影响排序）：

1. **第 6 周的 RKNN 转换**（占总风险的 ~40%）：算子不支持、INT8 量化掉点、前后处理形状对不齐。**这一周的坑必须在电脑上撞完**，因为 RKNN-Toolkit2 有仿真模式。
2. **字符识别方案**：自己训练 CRNN/标注字符 = +2 周；用 `rknn_model_zoo` 现成的 **LPRNet / PPOCR** = 几乎零成本（见下表）。
3. **国庆假期（10/1–10/7）**：出门就少一周，在家就是额外的一周。

**省时间的三招**：

1. **字符识别别自己训练** —— `rknn_model_zoo` 自带 [Car Plate Recognition / LPRNet](https://github.com/airockchip/rknn_model_zoo)（中文车牌，RK3588 单核 **586 FPS**），还有 PPOCR-Det/Rec 可备选。
2. **检测模型用 yolov8n，别上大的** —— RK3588 单核 **73.5 FPS**（INT8, 640×640），实时绰绰有余。
3. **板子的事现在并行做完** —— 验机 + 官方 demo 跑通，把"板子问题"提前排除，别等第 7 周才发现 WiFi 模块没插好。

**参考性能（RK3588 单核，官方 benchmark）**：

| 模型 | 输入 | 精度 | FPS |
|---|---|---|---|
| yolov8n（检测） | 640×640 | INT8 | **73.5** |
| LPRNet（车牌字符） | 24×94 | FP16 | **586.4** |
| PPOCR-Det（文字检测） | 480×480 | INT8 | 50.7 |
| PPOCR-Rec（文字识别） | 48×320 | FP16 | 73.9 |

> 这些数字**不含前后处理**，实际端到端帧率会低一些，但对你的项目完全够用——瓶颈通常不在 NPU，而在摄像头取帧和画图显示。

## 环境分层（现在就搞明白，能省你一周）

你最终会有**三个不同的 Python 环境**，各干各的，不要混：

| 环境 | Python | 装什么 | 用途 |
|---|---|---|---|
| `~/projects/py-basics/.venv` | 3.14（现有） | numpy / opencv | 第 2–3 周的学习练习，**继续用它** |
| `~/projects/rknn/.venv`（待建） | **3.10** | RKNN-Toolkit2、PyTorch、onnx | 阶段① 模型转换 + 仿真推理，**第 4 周就要建** |
| 板子上的系统 Python | 板子自带 | rknn_toolkit_lite2 / librknnrt | 板端推理 |

**为什么必须分开**：RKNN-Toolkit2 官方支持 **Python 3.6–3.12**（[官方 README](https://github.com/airockchip/rknn-toolkit2)），PyTorch 也还没有 3.14 的包。硬凑在一个环境里，结果是把现在好用的 3.14 环境搞坏。

**建议直接选 Python 3.10**：RKNN-Toolkit2、PyTorch、`rknn_model_zoo` 的例程全覆盖，网上的教程也最多。

```bash
# 用 conda（能装任意 Python 版本，装 RKNN-Toolkit2 也最省事）
conda create -n rknn python=3.10 -y
conda activate rknn
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu   # CPU 版，体积小一个数量级
python -c "import torch; print(torch.__version__)"
```

## 硬件采购清单

**推荐型号：Orange Pi 5B 8GB**

理由：
- RK3588S，**6 TOPS NPU**（和 Pro 一样）
- **板载 WiFi6**（普通版香橙派 5 没有）
- **板载 eMMC**（不用靠 SD 卡跑系统）
- **2 个 USB 3.0**（摄像头的带宽保障）
- 不需要 Pro 的 LPDDR5 / M.2 NVMe —— 对你这个项目零收益

| 项目 | 说明 | 参考价 |
|---|---|---|
| Orange Pi 5B 8GB | 选带 eMMC 的版本 | ¥700–800 |
| 电源 | **5V/4A 以上 Type-C**，普通手机头带不动 | ¥40–60 |
| 散热 | 散热片 + 5V 风扇，**别省**，降频会让你误判性能 | ¥30–60 |
| 存储 | 32GB A2 microSD（烧镜像）+ 网线 | ¥40 |
| 摄像头 | **USB 免驱 UVC，1080p**，别碰 MIPI 排线摄像头 | ¥100–200 |
| 串口模块 | **USB-TTL (CH340, 3.3V)** —— 起不来时的唯一眼睛 | ¥15 |
| **合计** | | **¥950–1200** |

### 省钱方案

| 手段 | 省 | 代价 |
|---|---|---|
| 二手（闲鱼） | ¥300–400 | 让卖家发 `rknpu/version` 截图确认 NPU 正常 |

### 购买渠道

**只在官方授权店买**（官网列出的渠道）：
- 官网商品页（含全部官方店铺链接）：`orangepi.cn`
- 天猫旗舰店 / 京东店铺 / 淘宝官方店

**警惕**：把"主频 2.4GHz"这种标准规格包装成"可选高配"来抬价的第三方卖家。RK3588S **本来就是** 4×A76@2.4GHz + 4×A55@1.8GHz，不存在选装。

### 别买

- ❌ 树莓派（闭源固件太多，学不了 BSP，NPU 也没有）
- ❌ 自己画 RK3588 板子（0.65mm BGA + LPDDR4X 等长走线，是另一份全职工作）
- ❌ 便宜的杂牌 RK3588 板（没有社区、没有固件、卡住没人能帮你）

## 心理准备

| 事实 | 说明 |
|---|---|
| **70% 的难度在模型转换** | 不在写代码。算子不支持、精度掉点会耗掉你最多时间 |
| **卡住是常态** | 不是你笨。嵌入式 AI 就是不断排错 |
| **串口比屏幕重要** | 板子起不来时，串口是你唯一的信息来源 |
| **不要囤课程** | 748 集的课不如自己写 748 行代码 |
| **每天记一条踩坑** | 这是你最有价值的资产 |
