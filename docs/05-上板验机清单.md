# 上板验机清单（Orange Pi 5 Plus / RK3588）

> **新板到手 48 小时内跑完这份清单。** 7 天退换期就是你的窗口，过了这个村只能走维修。
>
> 先记住一件事：**90% 的"板子坏了"其实是供电不够、镜像没烧好、SD 卡劣质、散热没装。**
> 按顺序查完再下结论。

---

## 0. 先确认你手上是哪块板

```bash
cat /proc/device-tree/model      # 例: Rockchip RK3588 OPi 5 Plus
```

| 项目 | 官方规格 |
|---|---|
| SoC | **RK3588**（不是 5B 的 RK3588S）8nm，4×A76@2.4GHz + 4×A55@1.8GHz |
| NPU | **6 TOPS**，支持 INT4/INT8/INT16/FP16 混合运算 |
| GPU | Mali-G610（OpenGL ES3.2 / OpenCL 2.2 / Vulkan 1.2） |
| 内存 | 8GB LPDDR4/4x（你买的是 8GB 版） |
| 存储 | QSPI NOR 16/32MB + **eMMC 闪存插座（外接 eMMC 模块）** + MicroSD + **M.2 2280 NVMe（PCIe 3.0 x4）** |
| 网络 | **2× 2.5G 网口（RTL8125BG）** + **M.2 E-Key 插 WiFi6/蓝牙模块** |
| 视频 | 2× HDMI 2.1 输出 + 1× Type-C DP + **1× HDMI 输入（4K@60）** |
| USB | 2× USB3.0、2× USB2.0、1× Type-C |
| 供电 | **Type-C 5V@4A** |
| 其它 | 5V FAN 接口、3Pin 调试串口、MaskROM / RECOVERY / 开关机键、RTC、红外、40Pin |

**和你原先计划的 5B 有两个关键差别，直接影响验机判断：**

1. **WiFi 不是板载的**，是插在 M.2 E-Key 上的模块 —— `wlan0` 不出现时，先查模块有没有插到底、天线有没有接上，别急着怀疑镜像。
2. **eMMC 是"插座 + 模块"**，不是焊在板上的 —— 你说的 64GB 是那块 eMMC 模块，插不到位系统就认不到盘。

**记下三样东西**（后面报错/售后都要用）：型号、镜像文件名和版本、内核版本（`uname -r`）。

---

## 1. 通电前 3 件事（别跳）

1. **散热片 + 风扇先装好。** RK3588 满载能到 80℃+，不装散热会降频，你会误判"性能不行"。
2. **电源必须 5V/4A 以上 Type-C。** 不要用电脑 USB 口，不要用手机快充头（PD 协商可能只给 2A 以下）——**供电不足的典型症状是：随机重启、WiFi 掉线、开机卡住**，看起来像板子坏，其实是电不够。
3. **目视 PCB**：元件歪斜、虚焊、焊盘发黑 → 先拍照留证再联系卖家。

---

## 2. 第一次开机：选一条路

| 路线 | 需要 | 优点 |
|---|---|---|
| **A. USB-TTL 串口**（推荐） | CH340 模块（¥15） | **能看到全部内核日志**，起不来时唯一的眼睛 |
| B. HDMI + 键鼠 | 显示器 | 直观，但看不到启动日志 |

**接法**：模块 TX → 板子 RX，模块 RX → 板子 TX，GND 对 GND（**不要接 VCC**，5 Plus 上是 3Pin 调试串口 GND/TX/RX）。
**波特率先试 1500000**（瑞芯微 BSP 默认），连上乱码再试 115200。
你 D 盘里已经有 MobaXterm，直接新建 Session → Serial → 选 COM 口 → 波特率 1500000。
官方对应章节：Wiki「调试串口的使用方法」。

**看灯**：红灯常亮 = 供电正常；绿灯闪 = 系统在跑。
**默认账号**：官方 Debian/Ubuntu 镜像一般是 `orangepi` / `orangepi`（以镜像说明为准），**第一次登录后立刻改密码**。

> 关键心态：**HDMI 不出画面别慌**，串口里看到 `Starting kernel ...` 一路滚下去，就说明板子是活的，问题在显示/镜像而不在硬件。

## 3. 一键自检：`setup/verify-board.sh`

把脚本传到板子上跑（脚本**只读**，不改系统配置；只有加 `--disk-test` 才会在 `$HOME` 写 512MB 临时文件测速，测完自动删）。

```bash
# ① 在 Windows PowerShell 里传上去（板子 IP 在板子上用 ip a 查看）

# ② 在板子终端里

bash -n ~/verify-board.sh              # 先只查语法，不执行任何东西
sudo bash ~/verify-board.sh | tee ~/verify-report.txt
```

没有网络连不上 `scp`，就把 `/mnt/d/嵌入式AI-车牌识别/setup/verify-board.sh` 用 U 盘拷进去，或者直接把文件内容复制粘贴成新文件。

脚本会逐项打 `[OK] / [注意] / [问题]`，最后给出汇总。

## 4. 关键指标对照表（"好"长什么样）

| 项目 | 命令 | 正常值 | 不正常说明什么 |
|---|---|---|---|
| 内存 | `free -h` | 总 **7.6–7.9 GiB** | 只有 3.x = 买到的是 4GB 版 |
| eMMC 模块 | `lsblk` | mmcblk* 约 **57–58 GiB** | 完全没有 = 模块没插到位；只有 28 左右 = 32GB 模块 |
| CPU | `nproc` | **8** | 4 = 板子不对 |
| 主频 | `cat /sys/devices/system/cpu/cpufreq/policy*/scaling_cur_freq` | A76 最高 **2400 MHz**、A55 **1800 MHz** | 明显偏低 = 正在降频（散热/供电） |
| 温度 | `cat /sys/class/thermal/thermal_zone*/temp` | 空闲 **40–55 ℃**，满载 **< 85 ℃** | > 85 会降频，先修散热 |
| **NPU** | `sudo cat /sys/kernel/debug/rknpu/version` | `RKNPU driver: v0.9.x` | **读不到 = 内核没带 NPU 驱动，必须换官方镜像** |
| NPU 负载 | `sudo cat /sys/kernel/debug/rknpu/load` | 跑模型时 0→100% 跳动 | 一直 0 = 模型没跑在 NPU 上 |
| 无线 | `iw dev` / `nmcli device` | 有 **wlan0** 且能连上 | 没有 wlan0 = M.2 模块没插好 / 天线没接 / 驱动问题 |
| 双网口 | `ip -br link` | **两个**有线口都在 | 只有一个 = 另一个口异常，记下来给卖家 |
| HDMI 输入 | `ls /dev/video*` | 接上信号源后出现 hdmirx 节点 | 没有 = 该镜像/设备树没启用 HDMI IN（看 Wiki「HDMI IN 的测试方法」） |
| GPU | `ls /dev/mali0` | 存在 | Server 版镜像可能没有，不影响跑 NPU |
| 存储报错 | `sudo dmesg -T \| grep -i mmc` | 无 error/timeout | 有错 → 记录原文，可能是 eMMC 虚焊 |

## 5. 三项"真验"（脚本只能看出存在性，这三项才叫验证）

### 5.1 NPU 三级验证（最重要）

**为什么要分三层**：`rknpu/version` 能打印只说明"内核里有这个驱动"，**不等于"NPU 真的能算"**。要跑到第三层才叫验证过。

#### 第 1 层：驱动在不在（1 分钟）

```bash
uname -r                                        # 内核版本
sudo cat /sys/kernel/debug/rknpu/version        # 期望: RKNPU driver: v0.9.x
sudo cat /sys/kernel/debug/rknpu/load           # 空闲时应是 Core0: 0%, Core1: 0%, Core2: 0%
cat /sys/class/devfreq/fdab0000.npu/cur_freq    # 当前 NPU 频率，单位 Hz（1000000000 = 1GHz）
cat /sys/class/devfreq/fdab0000.npu/available_frequencies
dmesg -T | grep -i rknpu
```

| 现象 | 说明 |
|---|---|
| 打印 `RKNPU driver: v0.9.x` | ✅ 内核带驱动。RK3588 有 **3 个 NPU 核**，load 会显示 Core0/1/2 |
| `No such file or directory` | ① 忘了 `sudo`；② debugfs 没挂载：`sudo mount -t debugfs none /sys/kernel/debug`；③ 镜像内核没带驱动 → **换官方镜像** |
| 找不到 `fdab0000.npu` | 设备树里 NPU 节点没启用（官方镜像一般都有） |

> 手动调 NPU 频率（平时不用动，压测时有用）：
> ```bash
> echo userspace | sudo tee /sys/class/devfreq/fdab0000.npu/governor
> echo 1000000000 | sudo tee /sys/class/devfreq/fdab0000.npu/max_freq
> ```

#### 第 2 层：用户态运行库在不在（2 分钟）

```bash
ls -l /usr/lib/librknnrt.so /usr/lib/aarch64-linux-gnu/librknnrt.so 2>/dev/null
strings /usr/lib/librknnrt.so | grep 'librknnrt version:'       # 期望: librknnrt version: 2.3.x
strings /usr/bin/rknn_server 2>/dev/null | grep 'build@'
```

> **`rknn_server` 缺失是正常的，别在这上面纠结。**
> 它只是"PC 通过 USB 直连板子推理"时的代理服务；**板端自己跑推理（`rknn_toolkit_lite2` / C API）完全不需要它**。
> 验证 NPU 真正要看的是 **`librknnrt.so`**（下面第 3 层的 demo 里也会把它和 driver 版本一起打印出来）。
>
> 另外记住 Linux 的一条脾气：**`grep` 没匹配到就一声不吭**（只把退出码设成 1），这不是命令坏了。想确认到底怎么回事，用：
> ```bash
> ls -l /usr/bin/rknn_server /usr/lib/librknnrt.so     # 先确认文件在不在
> which strings || sudo apt install -y binutils        # strings 是 binutils 里的工具
> strings /usr/bin/rknn_server | grep -i version; echo "退出码=$?"
> # 退出码 0 = 找到了；1 = 没匹配；127 = 命令不存在
> ```

**⚠️ 两个版本号体系别搞混**：`driver v0.9.x` 和 `librknnrt 2.3.x` **同时出现是正常的**（一个是内核驱动，一个是用户态库）。
真正需要一致的是：**PC 端 RKNN-Toolkit2 版本 ↔ 板端 librknnrt 版本**（都是 2.3.x）。不一致会出现"模型 load 失败"或"推理结果不对"。

缺 `librknnrt.so` 就从 rknpu2 里拷：

```bash
cd ~ && git clone -b v2.3.0 --depth 1 https://github.com/airockchip/rknn-toolkit2
sudo cp ~/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api/aarch64/* /usr/lib/
sudo cp ~/rknn-toolkit2/rknpu2/runtime/Linux/rknn_server/aarch64/usr/bin/* /usr/bin/
```

#### 第 2.5 层：版本对齐（老镜像必看）⭐

**症状**：`strings /usr/lib/librknnrt.so | grep 'librknnrt version:'` 出来是 **1.4.0 / 1.6.0** 这种 1.x（2023 年的老镜像常见）。

**为什么必须处理**：
- 你在 PC 上能装的 RKNN-Toolkit2 只有 **2.x**（现在最新 2.3.2），转出来的 `.rknn` 在 1.4.0 的 runtime 上会 **load 失败**（报类似 model version not supported）；
- 网上下载的预转换 `.rknn`（包括我给的 yolov5s_rk3588.rknn）基本也都是 2.x 工具链转的，同样 load 不了；
- 结果就是：**NPU 明明是好的，你却一个模型都跑不起来**，还容易误判成"板子 NPU 坏了"。

**先看驱动版本，再决定怎么走**：

```bash
sudo cat /sys/kernel/debug/rknpu/version
```

| 驱动版本 | 怎么办 |
|---|---|
| **≥ 0.9.6** | ✅ 直接换 2.3.x 运行库就能用（下面步骤 A），5 分钟搞定 |
| 0.9.0 – 0.9.5 | 先按步骤 A 试 2.3.x；不行就换中间版本（`git clone -b v2.0.0` / `v1.6.0`）逐一试 |
| 0.8.x 或更老 | 运行库和驱动是配套的，硬换大概率失败 → **步骤 B：刷较新的官方镜像**（板子上现在还什么都没有，重刷损失为零，是最省心的时机） |

**步骤 A：升级板端运行库（先备份！）**

```bash
# ① 备份原库 —— 这一步绝对不能省，新库不兼容可以回退
sudo cp /usr/lib/librknnrt.so /usr/lib/librknnrt.so.bak-1.4.0

# ② 拿新运行库（和 PC 端工具链同版本，选 v2.3.2 或 v2.3.0）
cd ~ && git clone -b v2.3.2 --depth 1 https://github.com/airockchip/rknn-toolkit2
ls ~/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api/aarch64/     # 里面有 librknnrt.so

# ③ 替换
sudo cp ~/rknn-toolkit2/rknpu2/runtime/Linux/librknn_api/aarch64/librknnrt.so /usr/lib/
sudo cp ~/rknn-toolkit2/rknpu2/runtime/Linux/rknn_server/aarch64/usr/bin/* /usr/bin/ 2>/dev/null

# ④ 验证版本变了
strings /usr/lib/librknnrt.so | grep 'librknnrt version:'        # 应显示 2.3.x
```

回退方法（万一新版跑不起来）：

```bash
sudo cp /usr/lib/librknnrt.so.bak-1.4.0 /usr/lib/librknnrt.so
```

**步骤 B：刷较新的官方镜像**

到 Orange Pi 官方资料下载页拿最新镜像重刷（eMMC 用 RKDevTool，SD 卡用 balenaEtcher）。刷完先跑第 1、2 层确认 `librknnrt` 已经是 2.x。

> **关键原则（第 6 周会再遇到一次）**：**PC 端 RKNN-Toolkit2 版本 = 板端 librknnrt 版本 = `rknn_toolkit_lite2` wheel 版本**，三者必须同代。
> 现在把板端对齐到 2.3.x，第 6 周你转模型时就不会两头打架。

#### 第 3 层：真跑一个模型（唯一标准）

**最省事的路径：直接下预转换好的 `.rknn`，不用先在 PC 上装工具链。**

```bash
# ① 依赖
sudo apt update && sudo apt install -y python3-pip git
python3 --version                     # 记下版本，决定装哪个 cp3xx wheel

# ② 板端推理库 rknn_toolkit_lite2
cd ~ && git clone -b v2.3.0 --depth 1 https://github.com/airockchip/rknn-toolkit2
ls ~/rknn-toolkit2/rknn-toolkit-lite2/packages/        # 看有哪些 cp3xx wheel
pip3 install ~/rknn-toolkit2/rknn-toolkit-lite2/packages/rknn_toolkit_lite2-2.3.0-cp310-*.whl
pip3 install opencv-python-headless                    # 板子上用 headless 版就够

# ③ 例程 + 预转换模型
cd ~ && git clone -b v2.3.0 --depth 1 https://github.com/airockchip/rknn_model_zoo
cd ~/rknn_model_zoo/examples/yolov5/model
wget https://github.com/zifeng-radxa/rknn_model_zoo/releases/download/yolov5s_rknn/yolov5s_rk3588.rknn

# ④ 跑一张图
cd ~/rknn_model_zoo/examples/yolov5/python
python3 yolov5.py --model_path ../../yolov5/model/yolov5s_rk3588.rknn --img_save
# 结果图在 ./result/ 下，scp 回电脑看
```

同时另开一个终端盯负载和温度：

```bash
watch -n1 'sudo cat /sys/kernel/debug/rknpu/load; cat /sys/class/thermal/thermal_zone*/temp'
```

**成功的样子**（关键几行）：

```
I RKNN: RKNN Runtime Information, librknnrt version: 2.3.0 ...
I RKNN: RKNN Driver Information, version: 0.9.8
I RKNN: RKNN Model Information, version: 6, toolkit version: 2.3.0, target platform: rk3588
bus  @ (91 129 555 464) 0.692
Detection result save to ./result/bus.jpg
```

**判定表**：

| 看到什么 | 结论 |
|---|---|
| 驱动版本 + librknnrt 版本都能打印 | 第 1、2 层通过 |
| 模型 load 成功、runtime 初始化成功 | ✅ **驱动 + runtime + NPU 三者真的通了** |
| 出检测框 **且** `rknpu/load` 有跳动 | ✅ **NPU 真的在算**（不是在 CPU 上算） |
| 参考吞吐（RK3588 单核，官方 benchmark）：yolov5s @640 ≈ 48 FPS、yolov8n @640 ≈ 73 FPS | 明显低一个量级 → 查降频 / 散热 / 模型版本 |
| 温度 < 85℃ | ✅ 散热够用（NPU 满载升温很快，散热片没装好立刻见分晓） |

**这一层常见的坑**：

| 报错/现象 | 原因 |
|---|---|
| `ModuleNotFoundError: No module named 'rknnlite'` | wheel 和板子 Python 版本不匹配（cp39 装到 3.10 上） |
| `ImportError: lib...: cannot open shared object file` | 缺 `librknnrt` 或依赖 → 回到第 2 层 |
| 模型 load 失败 / 结果明显不对 | PC 端工具链和板端 librknnrt 版本不一致（必须都是 2.3.x） |
| `rknpu/load` 一直是 0% | 模型其实跑在 CPU 上；或没加 `sudo` 看不到 |
| 提示 `from rknn.api import RKNN` 失败 | zoo 的 `py_utils/rknn_executor.py` 会自动回退到 rknnlite；装好 `rknn_toolkit_lite2` 后重跑即可 |
| 找不到 `--img_path` 参数 | 不同例程参数名不一样（yolov5 用 `--model_path` + `--img_save`）；先 `python3 yolov5.py -h` 看一眼 |

#### 最小验证路径（网络差 / 老镜像 / 只想快速确认 NPU 能算）⭐

`rknn-toolkit2` 仓库很大（几百 MB，从国内 clone 经常卡死），但其实**你只需要两个文件**。这条路径总共下载不到 20MB，**不用 clone 大仓库、不用 zoo、不用 opencv**。

**第 0 步（零下载，最快）：先看板子上有没有现成的**

```bash
find / -name '*.rknn' 2>/dev/null                              # 找现成的模型
ls ~/rknn-toolkit2/rknn-toolkit-lite2/examples/                 # 找现成的示例脚本
cd ~/rknn-toolkit2/rknn-toolkit-lite2/examples/resnet18
python3 test.py                                                # 一行跑完，不用写脚本
```

**成功的样子**（这就是 NPU 验证通过的凭证）：

```
W rknn-toolkit-lite2 version: 2.3.0
--> Load RKNN model
done
--> Init runtime environment
I RKNN: ... RKNN Runtime Information, librknnrt version: 2.3.0 ...
I RKNN: ... RKNN Driver Information, version: 0.9.6
I RKNN: ... target platform: rk3588 ...
--> Running model
-----TOP 5-----
[812] score:0.999680 class:"space shuttle"
done
```

**关键判读**：
- `librknnrt version` 和 `toolkit version` 都是 **2.3.0**、`target platform: rk3588` → 驱动 / 运行库 / 模型三者同代 ✅
- `W RKNN: query RKNN_QUERY_INPUT_DYNAMIC_RANGE error ...` → **静态形状模型的正常警告，可以忽略**（带 `W` 是警告，带 `E` 才是错误）
- 测试图就是 `space_shuttle_224.jpg`，模型认出 `space shuttle` 且置信度 **99.97%** → **最强证据不是"跑通了"，而是"算对了"**

> 实测经验：`rknn-toolkit2` 仓库里**自带 RK3588 的模型和示例**（`rknn-toolkit-lite2/examples/*/`，含 `resnet18`、`yolov5`、`mobilenet_v1`、`yolox_s`、`multiple_input_demo` 等）。如果板子上已经有这个仓库，**验证 NPU 只需要两行命令，一个字节都不用下载**。
> 反过来：**要下载某个文件之前，先 `find` 一下本机有没有现成的**——这条能省你半天。

**前提（走下面的完整流程时才需要）**：`librknnrt.so` 已经从 1.x 升级到 2.3.0（见第 2.5 层）。

```bash
# ① 板端 Python 推理库（约 550KB）
#    2.3.0 有 cp38 / cp39 / cp310 / cp311 / cp312 各版本 wheel，按你的 python3 -V 选
pip3 install rknn-toolkit-lite2==2.3.0 -i https://pypi.tuna.tsinghua.edu.cn/simple
python3 -c "from rknnlite.api import RKNNLite; print('rknnlite 导入成功')"
```

```python
import numpy as np

rknn = RKNNLite()
print("1) load_rknn      ->", rknn.load_rknn(MODEL))
print("2) init_runtime   ->", rknn.init_runtime())

fake = np.zeros((640, 640, 3), dtype=np.uint8)   # 假图：只为验证"能不能算"
```

## 6. 手动清单（脚本替代不了，逐项打勾）

- [ ] HDMI 出画面，分辨率正常（`xrandr` 或 `cat /sys/class/drm/card*-*/modes | head`）

## 附：风扇不转怎么办

RK3588 的风扇一般走 PWM，默认可能不启用，需要手动开或装控制脚本。先确认：

```bash
ls /sys/class/pwm/                       # 有没有 pwmchip
ls /sys/class/thermal/cooling_device*/   # 有没有 cooling device
dmesg -T | grep -i pwm
```

官方 Wiki 有「PWM 散热风扇的使用方法」一节，先照它来。另外这两个开源实现也可以参考：
- [dejanstojanovic/orangepi-pwm](https://github.com/dejanstojanovic/orangepi-pwm)
- [bfrengley/op5-pwm-fan](https://github.com/bfrengley/op5-pwm-fan)
