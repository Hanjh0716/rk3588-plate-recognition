## 0. 先建立直觉：异常是什么

**类比**：开车突然爆胎。

- **不处理** → 车毁人亡：Python 打印一大段 traceback，**整个程序当场退出**，后面的代码一行都不执行
- **处理** → 靠边换胎继续走：程序跳过出问题的那张图，接着处理下一张

技术上：Python 遇到"做不了的事"（`1/0`、`int("abc")`、打开不存在的文件），会**抛出一个异常对象**。如果一路上没人"接住"它，程序就崩。

**关键认知：异常不是一段错误文字，它是一个对象**，身上带着两样东西：

| 它带的东西 | 怎么取 | 例子 |
|---|---|---|
| **类型**（发生了什么） | `type(e).__name__` | `ValueError` |
| **消息**（细节） | `str(e)` 或 `print(e)` | `invalid literal for int() with base 10: 'abc'` |

## 1. 异常的"传播"路径（理解这个就懂了 80%）

```
        代码出错，抛出异常
              │
              ▼
    当前这行有没有被 try 包着？
       │                    │
      有                   没有
       │                    │
       ▼                    ▼
  跳到匹配的 except    往上一层（调用它的函数）找
  try 里剩下的代码         │
  全部跳过                 └─→ 一直找到最外层还没人接
                              → 打印 traceback，程序退出
```

所以你写 `try:` 的时候，脑子里要有一句：**"从这里开始，一旦出事，就直接跳到 except，中间的代码全部不执行。"**

## 2. `try / except / else / finally` 四段，各管什么

```python
try:
    print("① 可能出事的代码")
    raise ValueError("故意炸一下")
    print("② 这行永远不会执行")
except ValueError as e:
    print(f"③ 出事时执行: {e}")
else:
    print("④ 没出事才执行（可选，很少用）")
finally:
    print("⑤ 无论成功失败都执行（收尾用）")
```

| 段 | 什么时候执行 | 典型用途 |
|---|---|---|
| `try` | 总是 | 放"可能出事"的代码 |
| `except` | **出事时** | 接住、记录、跳过 |
| `else` | **没出事时**（可选） | 很少用；`try` 里只放最容易出错的那几行时，把其余逻辑放这儿 |
| `finally` | **无论怎样都执行** | 收尾：关文件、删临时文件、断连接 |

`finally` 的例子（Day 14 写 `report.txt` 会用到）：

```python
f = open("report.txt", "w")
try:
    f.write("成功 20 张\n")
finally:
    f.close()          # 就算上面写文件时抛异常，也保证关掉
```

> 你现在这个批处理脚本**不需要 `finally`**——没有需要收尾的资源。知道它是什么就够了。

## 3. `raise`：自己制造异常

有些"失败"，Python **根本不认为是异常**：

| 函数 | 失败时的表现 | 是异常吗 |
|---|---|---|
| `cv2.imread` | 返回 `None` | ❌ 安静的失败 |
| `cv2.imwrite` | 返回 `False` | ❌ 安静的失败 |
| `glob.glob` | 返回空列表 `[]` | ❌ 安静的失败 |
| `os.path.exists` | 返回 `False` | ❌ 安静的失败 |

**"安静的失败"必须用 `if` 判断**——`try/except` 抓不住它们！这就是 Day 13 的第一道防线。

那为什么还要 `raise`？因为**你希望两类失败走同一条处理通道**：

```python
img = cv2.imread(path)          # 安静的失败：返回 None
if img is None:
    raise ValueError("imread 返回 None")   # ← 主动"升级"成异常
```

一旦 `raise`，就会**立刻中断，跳到最近的 `except`**。这样：

- 后面 `resize`、`rectangle` 全部跳过（不会拿 `None` 去算，不会崩得莫名其妙）
- 处理方式统一在 `except` 里写一次：记录文件名 + 原因 + 计数

其他写法：

```python
raise ValueError("消息")               # 最常见
raise IOError(f"写不进去: {out_path}")  # 想表达"文件相关错误"时用
raise SystemExit("没有文件，直接结束")   # 相当于 sys.exit()
```

## 4. `except Exception as e` 逐字拆解

```python
except Exception as e:
#  ↑       ↑       ↑
# 接住   接哪一类   给它起个名字叫 e
```

- **`Exception`**：几乎所有"普通异常"的父类。写它就等于"只要是程序运行出错，我都接"。
- **`as e`**：把接住的那个**异常对象**绑定到变量 `e`，你就能读它的类型和消息。
- **`e` 怎么用**：

```python
print(type(e).__name__)     # 'ValueError'      类型名
print(str(e))               # 'imread 返回 None' 消息
print(f"{type(e).__name__}: {e}")   # 'ValueError: imread 返回 None'  ← Day 13 用的就是这个
```

### 异常家族树（看一眼就明白为什么要写 `Exception`）

```
BaseException
├── SystemExit          ← sys.exit() / raise SystemExit
├── KeyboardInterrupt   ← 你按 Ctrl+C
└── Exception           ← ★ 你平时要接的就是这一层
    ├── ValueError / TypeError / AttributeError / NameError
    ├── LookupError → IndexError / KeyError
    ├── ArithmeticError → ZeroDivisionError
    ├── OSError → FileNotFoundError / PermissionError / IsADirectoryError
    └── ImportError → ModuleNotFoundError
```

**注意 `KeyboardInterrupt` 不在 `Exception` 里。** 这正是下面这条规矩的技术原因：

### ❌ 绝对不要写裸 `except:`

```python
except:              # 接住"所有东西"，包括你按 Ctrl+C（想中断程序都中断不了）
    pass             # 而且什么都不记录 —— 等于销毁证据
```

```python
except Exception as e:      # ✅ 只接"程序错误"，Ctrl+C 照常生效
    print(f"... -> {type(e).__name__}: {e}")    # ✅ 一定要把 e 留下
```

**只统计"失败 3 张"却不写原因，等于没做错误处理。** 出了问题你还得再跑一遍、再猜一次。

### 想分开处理不同类型的异常

```python
try:
    ...
except ValueError as e:          # 先接具体的
    print("读图失败:", e)
except OSError as e:             # 再接文件相关的
    print("写文件失败:", e)
except Exception as e:           # 最后兜底
    print("其他错误:", e)
```

顺序有讲究：**具体的写前面，`Exception` 兜底放最后**（Python 从上往下匹配，第一个匹配上的就进去）。

## 5. 常见异常类型速查（附触发例子）

| 类型 | 什么情况 | 例子 |
|---|---|---|
| `ValueError` | 类型对，**值不对** | `int("abc")` |
| `TypeError` | **类型不对** | `"a" + 1`；`cv2.resize(None, ...)` |
| `AttributeError` | 对象**没有这个属性** | `None.shape` → `'NoneType' object has no attribute 'shape'`（你之前 `imshow` 报的就是它） |
| `NameError` | **变量名没定义**（打错字） | 用了 `imag` 但定义的是 `img` |
| `IndexError` | 列表/字符串**越界** | `[]` 上取 `[0]`；`files[99]` |
| `KeyError` | 字典**没有这个键** | `{"a": 1}["b"]` |
| `ZeroDivisionError` | 除以零 | `1 / 0` |
| `FileNotFoundError` | `open()` 的文件不存在 | `open("没有的文件")` —— **注意 `imread` 不会抛它，只返回 `None`** |
| `PermissionError` | 没权限 | 读 `chmod 000` 的文件 |
| `IsADirectoryError` | 把目录当文件读 | 对目录调 `imread` |
| `ModuleNotFoundError` | `import` 不存在的模块 | **忘记 `source .venv/bin/activate` 时最常见的报错** |
| `cv2.error` | OpenCV 自己的异常 | 断言失败：`(-215:Assertion failed)` |
| `KeyboardInterrupt` | 你按了 Ctrl+C | 不是 `Exception` 的子类 |

**两类失败，两道防线（整篇最重要的一张表）**：

| | 表现 | 用什么接 |
|---|---|---|
| **安静的失败** | `imread` → `None`；`imwrite` → `False`；`glob` → `[]` | **`if` 判断** |
| **抛出的异常** | `resize(None)`、坐标传 float、没权限、磁盘满 | **`try / except`** |

## 6. 看懂你的 day13.py：逐行注释版

```python
files = sorted(glob.glob(os.path.join(input_dir, "*.jpg")))    # ① 找文件
total = len(files)                # ② 总数：它是常量，后面只用不改（别再拿它当倒计时）

if total == 0:                    # ③ 空目录：只在循环外判一次
    raise SystemExit(f"未找到任何图像文件：{input_dir}")

ok_list, fail_list = [], []       # ④ 两个"记账本"

for index, path in enumerate(files, start=1):      # ⑤ index = 1,2,3...total
    name = os.path.basename(path)                  # ⑥ 先取文件名（放在 try 外面，后面 else 也要用）
    try:                                           # ⑦ 从这里开始"可能出事"
        img = cv2.imread(path)                     #    读图：失败只返回 None，不抛异常
        if img is None:                            # ⑧ 第一道防线：if 抓"安静的失败"
            raise ValueError("imread 返回 None（文件损坏 / 不是图片）")   # ⑨ 升级成异常

        small = cv2.resize(img, (w, h), interpolation=cv2.INTER_AREA)
        cv2.rectangle(small, (x1, y1), (x2, y2), (255, 0, 0), 2)      #    画图函数不要接返回值
        cv2.putText(small, name, (10, 30), cv2.FONT_HERSHEY_SIMPLEX, 0.7, (0, 255, 0), 2)

        out_path = os.path.join(output_dir, "processed_" + name)
        if not cv2.imwrite(out_path, small):       # ⑩ 第二道防线：又一个安静的失败
            raise IOError(f"imwrite 返回 False: {out_path}")

        ok_list.append(name)                       # ⑪ 记一笔"成功"
        print(f"[{index}/{total}] 成功: {name}")

    except Exception as e:                         # ⑫ ⑨⑩ 和任何其他异常，都汇到这一处
        fail_list.append((name, f"{type(e).__name__}: {e}"))   # ⑬ 记"文件名 + 原因"
        print(f"[{index}/{total}] 失败: {name} -> {type(e).__name__}: {e}")

print(f"\n共 {total} 张：成功 {len(ok_list)}，失败 {len(fail_list)}")      # ⑭ 对账
for name, reason in fail_list:                     # ⑮ 逐条列出失败原因
    print(f"  ✗ {name}: {reason}")
```

### 几个"看不懂"的地方，单独说

**⑦ → ⑨ → ⑫ 是怎么连起来的？**

```
第 7 行进入 try
   ↓
第 8 行发现 img 是 None（安静的失败）
   ↓
第 9 行 raise → 立刻中断！第 9 行后面的 resize/rectangle/imwrite 全部跳过
   ↓
直接跳到第 12 行 except，e 就是第 9 行造出来的那个 ValueError
   ↓
第 13 行把 (文件名, "ValueError: imread 返回 None...") 记进 fail_list
```

**⑬ 那行 `fail_list.append((name, f"{type(e).__name__}: {e}"))` 在干什么？**

- `(name, "...")` 是一个**元组**（把两个值打包成一个）
- 所以 `fail_list` 里每一条都是 `("broken.jpg", "ValueError: imread 返回 None")`
- 第 15 行 `for name, reason in fail_list:` 就能一次拆出两个值 → 打印成 `✗ broken.jpg: ValueError: ...`

**为什么成功/失败都要 print？** 因为你要**看得见进度**。批处理 100 张图，中间卡住时你得知道卡在第几张。

## 7. 报错怎么读（traceback 阅读法）

```
Traceback (most recent call last):
  File "day13.py", line 31, in <module>          ← ② 离你最近的那行"你的代码"
    img = cv2.imread(path)
  File ".../cv2/__init__.py", line 100, in ...   ← ① 中间这些是库内部，先忽略
cv2.error: ... (-215:Assertion failed) ...       ← ③ 真正的错误类型 + 消息
```

**读法（三步）**：

1. **看最后一行**：异常类型 + 消息 —— 这是"到底出了什么事"
2. **往上找最近的一条 `File "...你的文件...", line N`**：这是"在哪一行出的"
3. 中间全是库的内部调用栈，**先跳过**

**特殊情况**：如果看到

```
During handling of the above exception, another exception occurred:
```

说明**你的 `except` 代码块里又炸了**——比如在 `except` 里访问了一个不存在的变量。这种情况下真正的问题在**下面那一段**。

---

## 8. 三条铁律（背下来）

1. **安静的失败用 `if`，抛出的异常用 `try`** —— 两道防线，缺一不可
2. **永远别写裸 `except:`，也别 `pass` 掉** —— `except Exception as e` + 把 `e` 记下来
3. **`try` 的范围要小**：只包"可能出事的那几行"。一个 `try` 包 200 行，你就不知道是哪行炸的，也没法区分"图片坏了"和"你代码写错了"
   - *例外*：批量处理里把"整张图的处理"当成一个单元包起来是**合理**的，因为处置方式相同（跳过 + 记录）——这正是 day13 的做法。
