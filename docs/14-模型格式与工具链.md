# 模型格式与工具链扫盲：ONNX / RKNN / RKNN-Toolkit2

> 起因：**"RKNN-Toolkit2、ONNX、RKNN 都是什么？我的 Linux 基础不是很好。"**
>
> **先消除一个误会**：这三个是 **AI 工具链**的概念，**跟 Linux 几乎没有关系**。
> Linux 只是"运行它们的操作系统"。你完全不需要为了搞懂它们去补 Linux。（见 §八）

---

## 一、一句话各自是什么

| 名字 | 一句话 | 装在哪台机器上 | 它是"角色" |
|---|---|---|---|
| **ONNX** | 一种**通用的模型文件格式**（`.onnx`） | 不属于任何机器，就是个文件 | **交换格式**（像 PDF） |
| **RKNN** | 瑞芯微**私有的模型文件格式**（`.rknn`），只有 RK 的 NPU 能跑 | 文件，主要放在板子上 | **最终产物**（像 exe） |
| **RKNN-Toolkit2** | PC 上的**转换工具**（Python 库），把 ONNX 等转成 RKNN | **只装在 PC 上**（你的 WSL） | **编译器**（像 gcc） |

记住这三句就够：

```
ONNX          = 通用的"交换格式"        （谁都能读，但谁都不能直接跑）
RKNN          = 给 RK 芯片编译好的产物  （只有 RK 的 NPU 能跑）
RKNN-Toolkit2 = 把前者变成后者的编译器  （只在 PC 上，板子上没有）
```

## 二、⭐ 核心：一条链，看懂模型的一生

```
 ① 训练
    PyTorch / TensorFlow
              │
              │  训练得到权重
              ▼
       .pt / .pth  （PyTorch 的格式）
              │
              │  ② 导出（export）
              ▼
    ┌─────────────────────┐
    │       ONNX          │   .onnx
    │  通用中间格式        │   ← 所有人（任何框架、任何硬件厂商）都能读
    └─────────────────────┘
              │
              │  ③ RKNN-Toolkit2 转换（在 PC 上做）
              │     · 算子适配（NPU 不认的算子 → 换掉 / 回退 CPU）
              │     · 量化（FP32 → INT8）
              │     · 算子融合、内存优化
              ▼
    ┌─────────────────────┐
    │       RKNN          │   .rknn
    │  瑞芯微私有格式      │   ← 已经为这颗 NPU "编译"好的产物
    └─────────────────────┘
              │
              │  ④ 拷到板子上
              ▼
    ┌─────────────────────┐
    │  librknnrt / lite2  │   板端"运行时"
    │  （板子上真正干活）  │   ← 它读 .rknn，指挥 NPU 执行
    └─────────────────────┘
              │
              ▼
           NPU 算出结果
```

> 手里已经有了 `yolov5s_relu_rk3588.rknn`。**你现在是在"回头看自己做了什么"。**

## 三、ONNX 详解

### 3.1 为什么需要它：一个 N × M 的问题

```
框架有 N 种：  PyTorch / TensorFlow / PaddlePaddle / MXNet / Caffe ...
硬件有 M 种：  x86 CPU / ARM CPU / 瑞芯微 NPU / 英伟达 GPU / 华为昇腾 / 地平线 ...

如果两两直连，需要写 N × M 个转换器   →  爆炸
如果中间加一个统一格式，只需要 N + M 个 →  可行
                        ↑
                     这就是 ONNX
```

**ONNX = Open Neural Network Exchange（开放神经网络交换格式）**，
由微软和 Meta 发起，现在几乎所有框架和硬件厂商都支持。

> **类比（你熟悉的）**：
> - 做 PCB → **Gerber 文件**：不管你用 AD 还是 KiCad 画的，板厂都能读
> - 做 3D 打印 → **STL 文件**：不管 SolidWorks 还是 Fusion360，切片软件都能读
> - **AI 模型 → ONNX**：不管 PyTorch 还是 TF，各种硬件工具链都能读
>
> **ONNX 就是 AI 界的 Gerber。**

### 3.2 一个 `.onnx` 文件里装了什么

两样东西：

| 内容 | 说明 | 占比 |
|---|---|---|
| **计算图（graph）** | "有哪些算子、怎么连起来"——像一张电路图的网络表 | 极小 |
| **权重参数（weights）** | 几百万到几亿个**浮点数**（4 字节一个） | **99.9% 的体积** |

**具体到你手上的模型**：
```
yolov5s 有约 720 万个参数
× 4 字节（FP32）
≈ 29 MB          ← 这就是 .onnx 文件为什么这么大
```

### 3.3 ⚠️ ONNX 的关键局限：它只是"描述"，不能直接跑

`.onnx` 文件是一份**规格说明书**，不是可执行程序。要跑它必须有一个**运行时（runtime）**去"解释执行"：

- PC 上：`onnxruntime`（你已经装过，`pip install onnxruntime`）
- 板子上：也能装 `onnxruntime`（aarch64 版），但**它只用 CPU 跑，完全用不到 NPU** → 慢几十倍

**所以：ONNX 是"过程文件"，不是"最终交付物"。**

### 3.4 推荐工具：用 Netron 把模型"看"出来

**Netron** 是一个模型可视化软件（免费，Windows 上直接装）：
- 官网：`netron.app`（也能网页版打开）
- 拖一个 `.onnx` 进去 → **能看到每一层的名字、形状、算子类型**

**为什么强烈推荐**：你以后遇到"算子不支持""形状对不上"，**看图比看代码快 10 倍**。
比如你之前看到的 3 个输出 `(1,255,80,80)`，在 Netron 里能一路往上追溯是哪些层产生的。

## 四、RKNN 详解

### 4.1 为什么瑞芯微要自己搞一个格式

因为 **NPU 不是 CPU**：

| | CPU | NPU |
|---|---|---|
| 会执行什么 | 通用指令（加减乘除、跳转） | **只有它硬件电路里固化了的那些算子** |
| 灵活度 | 什么都能算 | **不认识的算子就完全算不了** |
| 效率 | 通用但慢 | 专用但极快（6 TOPS） |

所以不能把 ONNX 直接丢给 NPU。**必须先把模型"翻译"成 NPU 认识的指令**——
这个翻译动作，就是 RKNN-Toolkit2 干的活，产物就是 `.rknn`。

### 4.2 RKNN 这个名字

```
RK  = Rockchip（瑞芯微）
NN  = Neural Network（神经网络）
```

### 4.3 `.rknn` 文件里装了什么

| 内容 | 说明 |
|---|---|
| 图结构 | 翻译后的网络结构 |
| **量化后的权重** | 通常从 FP32（4 字节）压成 **INT8（1 字节）** |
| NPU 指令 | 针对这颗 NPU 排好的执行计划 |
| 算子融合结果 | 比如 Conv + BN + ReLU 合成一个操作，省时间省带宽 |

**体积对比（量级）**：
```
yolov5s.onnx   ≈ 29 MB   （FP32，4 字节/参数）
yolov5s.rknn   ≈  7 MB   （INT8，1 字节/参数）
                         ↓
                   体积约 1/4，速度还快好几倍
```

> 这就是"**量化**"：把浮点数换成整数。
> 精度会掉一点点（通常 < 1%），但速度和体积收益巨大。

### 4.4 ⚠️ 最关键的一点：RKNN **绑定了芯片型号**

```
yolov5s_relu_rk3588.rknn      ← 文件名里的 rk3588 不是装饰
```

| 常识 | 说明 |
|---|---|
| RK3588 的 `.rknn` **不能**给 RK3566 用 | 两个 NPU 的指令集不一样 |
| 换芯片 = **必须重新转换** | 拿 ONNX 重新跑一遍 Toolkit2 |
| 同一个芯片的**不同版本**也可能不兼容 | 所以才有版本对齐的坑（见 §5.3） |

> **类比（你熟悉的）**：
> `.onnx` 像 **C 源码**（跨平台，但得编译）
> `.rknn` 像 **编译好的机器码**（只能在这颗 CPU 上跑）
>
> 你不会把 STM32 的 `.elf` 拿去给 ESP32 跑，同理。

## 五、RKNN-Toolkit2 详解

### 5.1 它是"编译器 + 模拟器"，**不是运行时**

这是最容易搞混的一点：

| 它**是** | 它**不是** |
|---|---|
| 一个 **PC 上的 Python 库** | ❌ 板子上的运行程序 |
| **编译器**：ONNX → RKNN | ❌ 本身不能指挥 NPU |
| **模拟器**：在 PC 上假装是 NPU，跑一遍看效果 | ❌ 性能不代表真机（PC 仿真慢得多） |

**板子上装的是另外两个东西**：

| 板端组件 | 作用 | 类比 |
|---|---|---|
| `librknnrt.so` | **运行时库**，真正指挥 NPU 干活 | `libc` / `libcuda` |
| `rknn_toolkit_lite2` | 板上的 **Python API**，让你用 Python 调 `librknnrt` | Python 的 `ctypes` 封装 |
| `rknpu` 内核驱动 | 内核里的 NPU 驱动 | 显卡驱动 |
| `rknn_server` | 让 PC 通过 USB/网络**连板推理**用的服务 | 调试代理 |

### 5.2 ⭐ 两台机器上的分工（背下这张表）

| | **PC（你的 WSL）** | **板子（Orange Pi 5 Plus）** |
|---|---|---|
| 装什么 | **RKNN-Toolkit2** | `librknnrt` + `rknn_toolkit_lite2` + 驱动 |
| 干什么 | **转换**模型 + **仿真**验证 | **真机推理** |
| 输入 | `.onnx` / `.pt` | `.rknn` |
| 有没有 NPU | ❌ 没有（所以只能仿真，慢） | ✅ 有（所以快） |

```
你的 PC（编译）                     你的板子（运行）
┌──────────────────────┐          ┌──────────────────────┐
│  onnx2rknn.py        │          │  test.py             │
│  + RKNN-Toolkit2     │  .rknn   │  + rknn_toolkit_lite2│
│  ↓ 转换              │ ───────→ │  + librknnrt.so      │
│  yolov5s_rk3588.rknn │  拷贝    │  ↓                   │
│  （也可在 PC 上仿真） │          │  NPU 真机算          │
└──────────────────────┘          └──────────────────────┘
```

### 5.3 ⚠️ 版本对齐规则（你踩过这个坑）

```
   版本号必须一致             另一套编号，不用对齐
┌─────────────────────┐      ┌──────────────────┐
│ RKNN-Toolkit2 (PC)  │      │ rknpu 内核驱动    │
│ librknnrt    (板)   │  =   │ v0.9.6           │
│ lite2 wheel  (板)   │      │ （和上面的 2.3.0 │
│      都是 2.3.0      │      │   搭配使用没问题）│
└─────────────────────┘      └──────────────────┘
```

**你的实际状态（已经对齐好了）**：

| 组件 | 位置 | 版本 |
|---|---|---|
| RKNN-Toolkit2 | PC 的 conda `rknn` 环境 | **2.3.0** ✅ |
| librknnrt.so | 板子 `/usr/lib/` | **2.3.0** ✅（从 1.4.0 升上来的） |
| rknn_toolkit_lite2 | 板子（cp38） | **2.3.0** ✅ |
| rknpu 驱动 | 板子内核 | 0.9.6（另一套编号，OK） |

> **不对齐会怎样**：报错各种莫名其妙（"模型版本不匹配""无法加载"）。
> 这就是为什么你当时必须把板上的 `librknnrt.so` 从 1.4.0 换成 2.3.0。

### 5.4 为什么叫 "Toolkit2"

```
RKNN-Toolkit  （一代）：只支持老芯片（RK3399Pro、RK1808 等）
RKNN-Toolkit2 （二代）：支持 RK3562 / RK3566 / RK3568 / RK3588 等新一代
```

**你用的是二代，因为你的板子是 RK3588。**

### 5.5 它的四种典型用法（你只用过前两种）

```python
# ① PC 上的完整流程：ONNX → RKNN + 仿真推理   ← 你做过的
rknn.load_onnx(model="xxx.onnx")
rknn.build(do_quantization=True, dataset="dataset.txt")
rknn.init_runtime()                          # 不传 target = PC 仿真
outputs = rknn.inference(inputs=[img])

# ② PC 上只看转换结果（仿真）
rknn.load_rknn("xxx.rknn")
rknn.init_runtime()                          # ⚠️ 这样仿真会报错！见 §九

# ③ PC 连板推理（需要 USB/adb 连上板子）
rknn.load_rknn("xxx.rknn")
rknn.init_runtime(target="rk3588")           # 让板子的 NPU 算，结果回 PC
outputs = rknn.inference(inputs=[img])

# ④ 精度分析（找出量化掉点最多的层）—— 研究含量最高的用法
rknn.accuracy_analysis(inputs=[img], output_dir="./snapshot")
```

## 八、⭐ 关于"Linux 基础不好"——你真正需要的只有这些

### 8.1 先澄清：你的问题不在 Linux

| 你遇到的困难 | 其实是 |
|---|---|
| 搞不清 ONNX / RKNN / Toolkit | **AI 工具链**概念（本文档解决） |
| `ModuleNotFoundError` | **Python 虚拟环境**概念 |
| `LD_PRELOAD`、`libittnotify` | **动态链接库**概念（编程常识） |
| `patchelf --clear-execstack` | **可执行文件格式**概念（很底层，没人天生会） |
| 敲的命令不知道在干什么 | **命令行的读法**（下面 8.2 解决） |

**看出规律了吗**：没有一条是"Linux 系统管理"的问题。
**这些是"工具链/编程"的知识，别人也是在用的过程中学的。**

**结论：不要专门去补 Linux。用多少学多少。**

### 8.2 ⭐ 读懂一条 Linux 命令（这个比背命令有用 100 倍）

```bash
python3 ~/projects/rknn/onnx2rknn.py --int8 ~/datasets/images
   ↑            ↑                        ↑        ↑
 用哪个程序   哪个脚本                   选项名    选项的值
```

拆解规则：

| 位置 | 是什么 | 怎么认 |
|---|---|---|
| 第 1 个词 | **程序名** | `python3` / `ls` / `pip` |
| 后面的词 | **参数** | 有的以 `-` 开头（选项），有的是纯值（路径） |
| 以 `/` 开头 | **绝对路径**（从根目录算） | `/usr/lib/librknnrt.so` |
| 以 `~/` 开头 | 你的家目录 | `~/projects` = `/home/user/projects` |
| 以 `./` 开头 | **当前目录** | `./run.sh` |
| 没有斜杠 | 可能是命令，也可能是当前目录的文件 | 要看上下文 |

**两条最有用的习惯**：

```bash
ls -l /usr/lib/librknnrt.so     # 某个东西到底存不存在、多大、什么时候的
which python3                   # 我现在用的 python3 到底是哪一个（★ 虚拟环境问题的救星）
```

> `which` 这一条能解决你 90% 的"为什么我装的包用不了"——
> 因为它会告诉你**你正在用的到底是哪个 Python**。

### 8.3 真正需要会的，就这 8 类（每类一条）

| 场景 | 命令 | 说明 |
|---|---|---|
| 我在哪 | `pwd` | 当前目录 |
| 有什么 | `ls` / `ls -lh` | 列文件（`-lh` 带大小） |
| 进/出目录 | `cd 路径` / `cd ~` / `cd ..` | 回家 = `cd` |
| 看文件 | `cat 文件`（短）/ `less 文件`（长，`q` 退出） | |
| 找东西 | `find ~ -name "*.rknn"` | 全盘找某类文件 |
| 看报错/日志 | `命令 2>&1 \| tail -20` | 看最后 20 行 |
| 上一条命令成功没 | `echo $?` | **0 = 成功，其它 = 失败** |
| 装包/权限 | `pip install ...` / `sudo apt install ...` | `sudo` = 用管理员权限 |

**你已经在用这 8 类了**（你之前用过 `which`、`echo $?`、`find`）。

## 九、快问快答（这些疑问你一定有）

**Q1：`.rknn` 能不能在 PC 上跑？**
❌ **不能直接跑**。你之前就撞过这个墙：
```
E init_runtime: RKNN model that loaded by 'load_rknn' not support inference on the simulator
```
PC 上没有 NPU，`.rknn` 是给 NPU 的指令，PC 解释不了。
**想在 PC 上验证，必须走 `load_onnx → build → init_runtime → inference` 这一整条**（同一个进程里）。

**Q2：ONNX 能不能在板子上跑？**
✅ 能，但要装 aarch64 版 `onnxruntime`，而且**只用 CPU，完全用不到 NPU** → 慢几十倍。
既然板子有 NPU，就没理由这么做。

**Q3：为什么板子上不装 RKNN-Toolkit2？**
因为它**绑定了 x86_64 架构**（官方明确只支持 PC 的 Linux x86）。
而且它是"编译器"——**板子上只需要"运行"，不需要"编译"**。
（就像你不会在 STM32 上装 gcc。）

**Q4：我训练好的 `.pt` 能直接丢给板子吗？**
❌ 不能。NPU 不认 PyTorch 格式。必须：
```
.pt → .onnx → .rknn → 板子
```
（有些工具链支持 PyTorch 直接转，但**中转 ONNX 是最通用、最好排查的路**。）

**Q5：模型文件一般多大？**
看参数量。粗略算法：
```
体积 ≈ 参数量 × 字节数（FP32=4, FP16=2, INT8=1）
yolov5s：720 万参数 → FP32 约 29MB → INT8 约 7MB
```

**Q6：量化会掉多少精度？**
通常 **0.5% ~ 2%**（mAP），取决于**校准集质量**。
掉太多（>5%）一般是校准集选得不好（要选**真实场景**的图，不是随便 100 张）。

**Q7：我不做量化行不行？**
行（`do_quantization=False`，走 FP16），但：
- 体积大 4 倍、速度慢约一半
- **FP16 也未必精度不变**（有些算子会回退 CPU）
建议：**先 FP16 跑通流程，再做 INT8 优化。** ← 这正是你的节奏

**Q8：ONNX 和 RKNN 的"输出形状"会一样吗？**
不一定。**转换过程中算子融合、维度重排都可能改变输出布局**（比如 NCHW ↔ NHWC）。
所以每次转换后**都要重新验证输出形状和数值**——你就是这么做的。✅

## 十、一页总结

```
┌─────────────────────────────────────────────────────────────┐
│  ONNX         通用交换格式（AI 界的 Gerber / C 语言）         │
│               · 谁都能读，但谁都不能直接跑                    │
│               · 里面 99.9% 是权重浮点数                       │
├─────────────────────────────────────────────────────────────┤
│  RKNN         瑞芯微私有格式（编译产物，像 .elf）              │
│               · 只有 RK 的 NPU 能跑，且绑定芯片型号            │
│               · 权重通常是 INT8（体积约 1/4）                 │
├─────────────────────────────────────────────────────────────┤
│  Toolkit2     PC 上的编译器 + 模拟器（像 gcc）                │
│               · 只装 PC，板子上装的是 librknnrt + lite2       │
│               · 三处版本必须一致：Toolkit2 = librknnrt = lite2 │
├─────────────────────────────────────────────────────────────┤
│  流程:  .pt → .onnx → [Toolkit2 编译] → .rknn → [librknnrt] → NPU │
└─────────────────────────────────────────────────────────────┘
```
