## 0. 先想清楚：你要的是哪一种"Linux 强"

"学 Linux"是句废话，因为至少分五层。**对着层找目标，别对着书找。**

| 层 | 能力 | 标志 | 对应岗位 |
|---|---|---|---|
| ① 会用 | shell、包管理、权限、管道、vim | 在 Linux 里干活不别扭 | 所有人 |
| ② 会配 | systemd、网络、串口/CAN、GPIO、交叉编译 | 让程序在板上**自动运行** | 嵌入式应用开发 |
| ③ 会建 | U-Boot、内核编译、设备树、Buildroot/Yocto | 能做出**自己的系统镜像** | 嵌入式 Linux 工程师 |
| ④ 会写驱动 | 内核模块、I2C/SPI/GPIO 子系统、设备树 binding | 能让**别人写的硬件**在 Linux 上跑 | 驱动/底层工程师 |
| ⑤ 会调优 | perf、ftrace、内存/启动时间优化、实时性 | 能回答"为什么慢/为什么崩" | 系统/性能工程师 |

**你现在在 ①，正在 ② 的路上。**建议目标：**扎实到 ③，能碰 ④**。

> ⚠️ **别去学"Linux 运维"那一路**（K8s、集群、Ansible）。那是另一个职业方向，和你的硬件背景不叠加，学了也浪费。

## 2. 学习原则（照你自己定的规矩来）

1. **项目驱动**：一个项目挂 3–5 个 Linux 知识点，不为了学而学
2. **只在需要时学**：不囤课程，不背命令大全
3. **必须在板子上验证**：WSL 里敲一遍不算会，板子上跑起来才算
4. **每周记一条踩坑**：`docs/踩坑记录.md` 是你最值钱的资产

> 有一个很好的切入点：**你其实已经在用 Linux 的内核接口了。** `cat /sys/kernel/debug/rknpu/load` 能看 NPU 负载——`/sys` 里的每个文件都是驱动暴露出来的。这就是"设备驱动"那一层的入口，顺着它往下挖就行。

## 6. 怎么判断自己真的会了（自检清单）

到明年 1 月，如果你能**不看教程**做到下面这些，就已经超过大多数只会"跑通 demo"的人了：

- [ ] 写一个 systemd unit，让程序开机自启、崩了自动重启、日志能 `journalctl -u` 查看
- [ ] 在电脑上交叉编译一个 C 程序，`scp` 到板子上直接跑起来（不依赖板子上的编译器）
- [ ] 读懂一段 `.dts`，并加一个 overlay 让某个 GPIO 上的 LED 亮起来
- [ ] 写一个字符设备驱动，`insmod` 后在 `dmesg` 里看到自己的打印，并能通过 `/dev` 或 `/sys` 访问
- [ ] 让 RK3588 和 STM32 通过 CAN 互相收发数据，掉线能自动恢复
- [ ] 用 `perf` 或 `htop` 找出一个程序的瓶颈，并说清楚瓶颈在哪一层
- [ ] 用 Buildroot 做出一张能启动、能跑你自己程序的 SD 卡镜像
